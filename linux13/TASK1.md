# 1. 정적 라이브러리와 동적 라이브러리의 차이

## ① 정의

### 정적 라이브러리 (Static Library)
- 확장자: `.a` (Linux)
- 컴파일된 라이브러리 코드를 실행 파일에 포함하는 방식이다.
- 빌드 과정의 링크 시점에 라이브러리 코드가 실행 파일에 결합된다.

### 동적 라이브러리 (Dynamic Library)
- 확장자: `.so` (Linux)
- 라이브러리 코드를 실행 파일에 직접 포함하지 않고 별도의 파일로 관리한다.
- 일반적으로 실행 시점에 동적 로더가 공유 라이브러리를 메모리에 적재하고 연결한다.

## ② 링크 시점

| 구분 | 정적 라이브러리 | 동적 라이브러리 |
|---|---|---|
| 링크 시점 | 빌드 시점 | 빌드 시 동적 링크 정보 기록, 실행 시 연결 |
| 실행 파일 크기 | 상대적으로 큼 | 상대적으로 작음 |
| 라이브러리 파일 | 실행 시 별도 파일 불필요 | 실행 환경에 별도 파일 필요 |
| 메모리 사용 | 코드 공유 측면에서 불리할 수 있음 | 여러 프로세스가 코드 영역 공유 가능 |
| 배포 | 실행 파일 배포가 비교적 간단 | 라이브러리 의존성 관리 필요 |
| 업데이트 | 라이브러리 변경 시 재링크 필요 | ABI 호환 시 라이브러리 교체 가능 |

## ③ 장단점

### 정적 라이브러리
**장점**
- 실행 시 외부 라이브러리 파일에 대한 의존성이 줄어든다.
- 배포 및 실행 환경 관리가 비교적 간단하다.

**단점**
- 실행 파일의 크기가 커질 수 있다.
- 라이브러리가 변경되면 실행 파일을 다시 링크해야 한다.
- 여러 프로그램에서 동일 코드가 중복 포함될 수 있다.

### 동적 라이브러리
**장점**
- 실행 파일 크기를 줄일 수 있다.
- 여러 프로그램이 라이브러리의 코드 영역을 공유할 수 있다.
- ABI 호환성을 유지하면 실행 파일을 재빌드하지 않고 라이브러리를 업데이트할 수 있다.

**단점**
- 실행 환경에 필요한 라이브러리가 존재해야 한다.
- 라이브러리 버전이나 경로 문제로 실행 오류가 발생할 수 있다.

# 2. GCC의 -I, -l, -L, -g, -v 옵션

| 옵션 | 기능 | 사용 예시 |
|---|---|---|
| `-I` | 헤더 파일 검색 경로 지정 | `gcc -I./include main.c` |
| `-l` | 링크할 라이브러리 지정 | `gcc main.c -lm` |
| `-L` | 라이브러리 파일 검색 경로 지정 | `gcc main.c -L./lib -lmylib` |
| `-g` | 디버깅 정보 생성 | `gcc -g main.c -o main` |
| `-v` | 컴파일 과정 및 GCC 내부 명령 상세 출력 | `gcc -v main.c` |

## ① -I 옵션
- 헤더 파일을 검색할 디렉터리를 추가한다.
- `#include`로 사용하는 헤더 파일이 별도 경로에 있을 때 사용한다.

## ② -l 옵션
- 링크할 라이브러리를 지정한다.
- 예를 들어 `-lm`은 수학 라이브러리(libm)를 링크한다.

## ③ -L 옵션
- 링커가 라이브러리를 검색할 디렉터리를 추가한다.
- 일반적으로 `-l` 옵션과 함께 사용한다.

## ④ -g 옵션
- 실행 파일에 디버깅 정보를 포함한다.
- GDB 등을 사용하여 변수, 함수 및 소스 코드 위치를 확인할 수 있다.

## ⑤ -v 옵션
- GCC 버전 및 컴파일·링크 과정에서 실행되는 명령과 설정 정보를 상세히 출력한다.
- 컴파일 과정이나 설정을 확인할 때 사용한다.

# 3. 디버그 모드와 릴리즈 모드의 차이

## ① 디버그 모드 (Debug Mode)

- 대표 옵션: `-g`
- 디버깅 정보를 생성하여 프로그램 오류를 분석하기 쉽게 한다.
- GDB로 변수 값, 함수 호출, 소스 코드 위치 등을 확인할 수 있다.
- 일반적으로 최적화 옵션을 사용하지 않는 `-O0`과 함께 사용한다.
- 디버깅 정보 때문에 실행 파일 크기가 증가할 수 있다.

예시:
`gcc -g -O0 main.c -o main`

## ② 릴리즈 모드 (Release Mode)

- 대표 옵션: `-O1`, `-O2`, `-O3`
- 컴파일러 최적화를 통해 실행 속도나 코드 효율을 개선하는 데 중점을 둔다.
- 최적화 수준이 높아질수록 더 다양한 최적화 기법을 적용한다.
- 최적화로 인해 변수나 명령어의 대응 관계가 바뀌어 디버깅이 어려워질 수 있다.
- 높은 최적화 수준이 항상 더 빠른 실행이나 작은 파일 크기를 보장하지는 않는다.

### 최적화 옵션 비교

| 옵션 | 설명 |
|---|---|
| `-O0` | 최적화 비활성화 (기본값) |
| `-O1` | 기본적인 최적화 수행 |
| `-O2` | 다양한 최적화를 적용하여 성능 개선 |
| `-O3` | `-O2`보다 적극적인 최적화 수행 |

예시:
`gcc -O2 main.c -o main`

## ③ 디버그 모드와 릴리즈 모드 비교

| 구분 | 디버그 모드 | 릴리즈 모드 |
|---|---|---|
| 대표 옵션 | `-g -O0` | `-O1`, `-O2`, `-O3` |
| 목적 | 오류 분석 및 디버깅 | 실행 성능 최적화 |
| 디버깅 정보 | 일반적으로 포함 | 일반적으로 생략 |
| 최적화 | 일반적으로 비활성화 | 활성화 |
| 실행 속도 | 상대적으로 느릴 수 있음 | 상대적으로 빠를 수 있음 |
| 디버깅 편의성 | 높음 | 상대적으로 낮음 |

**주의:** `-g`는 디버깅 정보를 생성하는 옵션이며, 최적화를 직접 비활성화하지 않는다. 따라서 `-g`와 `-O2`를 함께 사용할 수도 있다.

## ④ 핵심 정리

- 정적 라이브러리: 빌드 시 라이브러리 코드를 실행 파일에 포함한다.
- 동적 라이브러리: 라이브러리를 별도로 관리하며 실행 시 동적 로더가 연결한다.
- `-I`: 헤더 검색 경로
- `-l`: 링크할 라이브러리
- `-L`: 라이브러리 검색 경로
- `-g`: 디버깅 정보 생성
- `-v`: 컴파일 과정 상세 출력
- 디버그 모드: 오류 분석 중심 (`-g -O0`)
- 릴리즈 모드: 실행 성능 최적화 중심 (`-O1`, `-O2`, `-O3`)
