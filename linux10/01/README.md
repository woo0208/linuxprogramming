
# 프로그램 개발 과정 및 빌드 결과 파일 확인

## 1. 프로그램 개발 과정

프로그램 개발 과정은 일반적으로 **편집 → 선행처리(전처리) → 컴파일 → 링크 → 실행**의 5단계로 이루어진다.

### ① 편집 (Editing)

- 프로그래머가 C언어 등의 프로그래밍 언어를 사용하여 소스코드를 작성하는 단계이다.
- Visual Studio와 같은 개발 도구(IDE)를 이용하여 코드를 작성하고 수정한다.
- 작성한 C언어 소스코드는 `.c` 확장자로 저장된다.
- 예: `main.c`

### ② 선행처리 (Preprocessing)

- 컴파일 전에 소스코드의 전처리 지시문을 처리하는 단계이다.
- `#include`를 통해 헤더 파일의 내용을 포함한다.
- `#define`으로 정의한 매크로를 치환한다.
- `#if`, `#ifdef` 등의 조건부 컴파일 지시문을 처리한다.
- 전처리 결과는 컴파일러에 전달되며, 별도의 파일로 저장할 경우 일반적으로 `.i` 확장자를 사용한다.

### ③ 컴파일 (Compilation)

- 전처리가 완료된 소스코드를 컴퓨터가 처리할 수 있는 기계어 형태로 변환하는 단계이다.
- 컴파일러는 코드의 문법과 자료형 등을 검사한다.
- 문법 오류가 발생하면 오류 메시지를 출력하며, 정상적인 목적 파일 생성이 실패할 수 있다.
- Visual Studio의 C/C++ 빌드 환경에서는 컴파일 결과로 `.obj` 목적 파일이 생성된다.
- 예: `main.c` → `main.obj`

※ 엄밀하게는 컴파일 과정에 어셈블리 코드 생성과 어셈블 단계가 포함될 수 있다.

### ④ 링크 (Linking)

- 컴파일 과정에서 생성된 목적 파일과 필요한 라이브러리를 결합하는 단계이다.
- 여러 소스 파일에서 만들어진 목적 파일을 하나의 실행 파일로 연결한다.
- 다른 파일에서 정의된 함수나 라이브러리 함수의 참조를 해결한다.
- 필요한 함수의 정의를 찾지 못하면 링크 오류가 발생할 수 있다.
- Windows의 Visual Studio 환경에서는 정상적으로 링크가 완료되면 일반적으로 `.exe` 실행 파일이 생성된다.
- 예: `main.obj` + 라이브러리 → `프로젝트명.exe`

### ⑤ 실행 (Execution)

- 링크가 완료되어 생성된 실행 파일을 운영체제가 실행하는 단계이다.
- 운영체제는 실행 파일을 메모리에 적재하고 프로그램 실행을 시작한다.
- 프로그램의 명령어가 CPU에서 수행되며 계산, 입력, 출력 등의 기능이 동작한다.
- 실행 중 잘못된 메모리 접근이나 0으로 나누기 등의 문제가 발생하면 런타임 오류가 발생할 수 있다.

## 2. 프로그램 개발 과정 요약

| 단계 | 주요 작업 | 결과 |
|---|---|---|
| 편집 | 소스코드 작성 및 수정 | `.c` |
| 선행처리 | 헤더 파일 포함, 매크로 치환 | 전처리된 소스코드 |
| 컴파일 | 소스코드를 기계어로 변환 | `.obj` |
| 링크 | 목적 파일과 라이브러리 연결 | `.exe` |
| 실행 | 실행 파일을 메모리에 적재하여 수행 | 프로그램 실행 결과 |

**전체 과정**

편집(`main.c`) → 선행처리 → 컴파일(`main.obj`) → 링크(`프로젝트명.exe`) → 실행

## 3. 프로젝트 빌드 후 파일 위치 확인

Visual Studio에서 C언어 프로젝트를 빌드한 후 소스 파일(`.c`), 목적 파일(`.obj`), 실행 파일(`.exe`)의 위치를 파일 탐색기로 확인한다.

### ① 소스 파일 (.c)

- 프로그래머가 직접 작성한 C언어 소스 파일이다.
- 일반적으로 프로젝트 폴더 내부에 저장된다.

예시 위치:

`C:\Users\사용자명\source\repos\프로젝트명\프로젝트명\main.c`

**[파일 탐색기 검색 화면 첨부]**

→ 파일 탐색기에서 프로젝트 폴더를 열고 `*.c`를 검색한 결과 화면을 캡처하여 첨부한다.

### ② 목적 파일 (.obj)

- 소스코드를 컴파일하여 생성한 목적 파일이다.
- Visual Studio에서는 일반적으로 중간 빌드 결과 폴더에 저장된다.
- Debug 또는 Release 설정 및 플랫폼 설정에 따라 저장 경로가 달라질 수 있다.

예시 위치:

`C:\Users\사용자명\source\repos\프로젝트명\프로젝트명\x64\Debug\main.obj`

**[파일 탐색기 검색 화면 첨부]**

→ 파일 탐색기에서 프로젝트 폴더를 열고 `*.obj`를 검색한 결과 화면을 캡처하여 첨부한다.

### ③ 실행 파일 (.exe)

- 컴파일과 링크가 완료된 최종 실행 파일이다.
- Windows 운영체제에서 실행할 수 있는 프로그램 파일이다.
- 일반적으로 Debug 또는 Release 출력 폴더에 저장된다.

예시 위치:

`C:\Users\사용자명\source\repos\프로젝트명\x64\Debug\프로젝트명.exe`

**[파일 탐색기 검색 화면 첨부]**

→ 파일 탐색기에서 프로젝트 폴더를 열고 `*.exe`를 검색한 결과 화면을 캡처하여 첨부한다.

※ 위 경로는 Visual Studio의 일반적인 설정을 기준으로 한 예시이며, 실제 저장 위치는 프로젝트 설정에 따라 달라질 수 있다.

## 4. 실습 결과 및 결론

프로그램 개발 과정은 소스코드를 작성하는 편집 단계부터 전처리, 컴파일, 링크를 거쳐 최종적으로 실행하는 순서로 진행된다.

프로젝트를 빌드하면 작성한 소스 파일(`.c`)을 기반으로 목적 파일(`.obj`)이 생성되고, 링커가 필요한 목적 파일과 라이브러리를 결합하여 실행 파일(`.exe`)을 생성한다.

이를 통해 `.c` 파일은 사람이 작성한 소스코드, `.obj` 파일은 컴파일된 중간 결과물, `.exe` 파일은 실제 실행할 수 있는 최종 결과물이라는 차이를 확인할 수 있다.
